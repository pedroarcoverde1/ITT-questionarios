## 2. Texto para colar

```
AVALIAÇÃO PÓS-TRILHA — HTML E CSS PARA PROJETOS WEB

Contexto: questionário aplicado depois de a trilha ser concluída, em uma ONG que ensina
computação para adolescentes do ensino fundamental II e médio. O estudante não tinha
experiência em desenvolvimento web antes da trilha e construiu sites completos publicados
no GitHub Pages. A trilha não cobre JavaScript — não use JavaScript em nenhum item.

ASSUNTOS

C1 - Como a internet e a web funcionam
  Cobrar: colocar em ordem os passos entre digitar um endereço e a página aparecer; o que
  o DNS faz, em uma frase; o papel do cliente e o do servidor em um exemplo concreto.
  Erros típicos, para virar alternativa errada: achar que internet e web são a mesma
  coisa; supor que o site inteiro fica salvo no navegador; confundir o DNS com o servidor
  que hospeda o site; achar que o Wi-Fi é a internet.

C2 - HTML semântico
  Cobrar: dado um conteúdo descrito em texto, escolher a tag semântica adequada (header,
  nav, main, section, article, footer); corrigir uma hierarquia de títulos que pula de h1
  para h3; reconhecer o alt como requisito de uma imagem.
  Erros típicos: usar div para tudo em vez da tag semântica correta; escolher a tag de
  título pelo tamanho visual e não pela hierarquia; esquecer de fechar tags ou aninhá-las
  na ordem errada; omitir o alt das imagens.

C3 - Seletores e propriedades CSS
  Cobrar: dado um HTML e um CSS, apontar quais elementos recebem determinado estilo;
  escolher entre classe e id conforme o estilo se repita ou não; resolver um conflito
  simples de especificidade entre duas regras.
  Erros típicos: confundir o seletor de classe (.) com o de id (#); repetir o mesmo id em
  vários elementos; esperar que a última regra do arquivo sempre vença, ignorando
  especificidade; esquecer a unidade (px, rem) no valor.

C4 - Box model e organização do código
  Cobrar: dado um elemento com width, padding e border, identificar o espaço que ele
  ocupa; escolher entre margin e padding para resolver um espaçamento descrito; reconhecer
  quando criar uma classe reutilizável em vez de repetir regras.
  Erros típicos: trocar margin por padding e vice-versa; ignorar o efeito de box-sizing no
  cálculo da largura; resolver espaçamento com vários <br> em vez de CSS; escrever estilo
  inline em vez de usar o arquivo CSS.

C5 - Formulários utilizáveis e validados
  Cobrar: dado um dado a coletar (e-mail, data, arquivo), escolher o input adequado;
  associar label e campo via for/id; reconhecer o papel de required e de name no envio.
  Erros típicos: usar input type="text" para tudo; esquecer o name e perder o dado no
  envio; agrupar radios sem o mesmo name, permitindo marcar mais de um; usar placeholder
  como se fosse label.

C6 - Acessibilidade digital e SEO técnico
  Cobrar: identificar uma barreira de acessibilidade em um trecho de HTML; explicar para
  que serve o texto alternativo de uma imagem; reconhecer o papel da meta description e do
  title na busca.
  Erros típicos: achar que acessibilidade é só para pessoas cegas; usar aria-label onde o
  HTML semântico já resolveria; repetir palavras-chave achando que melhora o SEO;
  confundir o title da aba com o h1 da página.

C7 - Layouts com Flexbox e CSS Grid
  Cobrar: dado um layout desenhado, justificar a escolha entre Flexbox e Grid; prever o
  resultado visual de justify-content e align-items; reconhecer que display: flex vai no
  contêiner, não nos filhos.
  Erros típicos: aplicar as propriedades de flex nos itens em vez do contêiner; confundir
  o eixo principal com o transversal; usar Grid para alinhar um único elemento; esquecer
  de definir flex-direction e estranhar o resultado.

C8 - Responsividade com mobile first e media queries
  Cobrar: prever qual bloco de media query se aplica a uma dada largura de tela; explicar
  o princípio mobile first em uma frase; escolher unidade relativa (%, rem, vw) em vez de
  px fixo quando o layout deve adaptar.
  Erros típicos: escrever media query com min-width achando que vale para telas menores;
  definir larguras fixas em px e quebrar o layout no celular; esquecer a meta tag
  viewport; criar um breakpoint por aparelho em vez de por conteúdo.

FORA DE ESCOPO - não cobre nada disso: JavaScript em qualquer forma, pré-processadores
(Sass, Less), frameworks CSS, animações complexas, container queries, design system
completo, validação via script, envio ao back-end, auditoria WCAG completa, SEO off-page e
link building, configuração de servidores e criptografia.

REDAÇÃO E CALIBRAGEM

- Português brasileiro, linguagem direta, sem jargão corporativo. Enunciado de no máximo
  3 linhas.
- Contextos concretos e próximos do público: página de um jogo, perfil, blog da escola,
  cardápio, portfólio, site de um evento.
- Quando o item trouxer código, use HTML e CSS com no máximo 15 linhas, sem JavaScript,
  sem frameworks e sem pré-processadores. Descreva em texto o efeito visual esperado: o
  estudante não vai ver a página renderizada.
- As alternativas erradas devem sair dos erros típicos listados em cada assunto, nunca ser
  aleatórias: toda alternativa errada precisa ser plausível para quem entendeu em parte.
- Não pergunte nada sobre a plataforma Alura, nomes de instrutores, duração de curso ou
  ordem dos módulos. Avalie conhecimento de HTML e CSS, não memória do curso.
- Calibragem cognitiva do conjunto: cerca de 7 itens de compreensão, 10 de aplicação e 3
  de análise ou avaliação.
```
