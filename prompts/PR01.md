# Questionário PR01 · A partir do zero: iniciante em programação

> Gerado a partir de `cursos/PR01-iniciante-programacao.json`.
> A **seção 2** é o texto que se cola no campo de prompt da plataforma — e só ele.
> A **seção 3** é o roteiro de montagem: quantas questões por tema e qual botão selecionar.

## 1. Como montar

1. Cole o texto da seção 2 no campo de prompt, uma vez.
2. Percorra as linhas da seção 3 de cima para baixo. Em cada linha, selecione o botão
   indicado, peça a quantidade indicada e informe o tema daquela linha.
3. Confira os totais no fim da seção 3: 20 itens, sendo 2 dissertativas.

## 2. Texto para colar

```
AVALIAÇÃO PÓS-TRILHA — INICIANTE EM PROGRAMAÇÃO (JAVASCRIPT)

Contexto: questionário aplicado depois de a trilha ser concluída, em uma ONG que ensina
computação para adolescentes do ensino fundamental II e médio. Esta é a primeira trilha de
programação do estudante — não pressuponha nenhuma outra linguagem, nem orientação a
objetos, nem HTML/CSS, nem terminal além do básico de Git. Todo código em JavaScript
rodando no navegador.

ASSUNTOS

C1 - A programação como área
  Cobrar: o que um programa faz; o que é um algoritmo em uma frase; as frentes de atuação
  (front-end, back-end, mobile, dados); diferença entre linguagem de programação e
  ferramenta (editor, navegador, repositório).
  Erros típicos, para virar alternativa errada: achar que front-end e back-end são
  linguagens e não camadas; achar que programa é só aplicativo de celular; supor que o
  navegador compila o código para outra linguagem.

C2 - Variáveis, tipos e entrada/saída
  Cobrar: prever o valor final de uma variável depois de uma sequência de atribuições;
  escolher entre let e const conforme o valor mude ou não; montar uma mensagem
  concatenando texto com o conteúdo de uma variável; ler dados e exibir resultado.
  Erros típicos: somar número com texto e obter concatenação em vez de soma; reatribuir
  uma const; usar aspas em volta do nome da variável, confundindo nome com valor; usar =
  onde queria ==.

C3 - Condicionais e operadores
  Cobrar: traduzir uma regra em linguagem natural ("se a nota for 7 ou mais, aprovado")
  para um if correto; prever qual ramo de um if / else if / else executa para um dado
  valor; combinar duas condições com && ou ||.
  Erros típicos: usar = em vez de == ou === na comparação; trocar && por || e inverter a
  lógica; encadear ifs independentes onde o caso pedia else if; ordem errada dos testes
  deixando um ramo inalcançável.

C4 - Laços
  Cobrar: contar quantas vezes um laço executa em um dado intervalo; rastrear o valor de
  um acumulador ao longo das iterações; justificar while quando o número de repetições
  não é conhecido de antemão.
  Erros típicos: laço infinito por não atualizar a variável de controle; erro de 1 a mais
  ou a menos nos limites do for; declarar o acumulador dentro do laço e zerá-lo a cada
  volta; confundir a condição de continuar com a de parar.

C5 - Funções com parâmetros e retorno
  Cobrar: identificar qual trecho repetido deveria virar função; distinguir o que a função
  devolve com return do que ela mostra na tela; prever a saída de uma chamada com
  argumentos diferentes.
  Erros típicos: definir a função e nunca chamá-la; usar o resultado de uma função que só
  imprime e não retorna; trocar a ordem dos argumentos na chamada; usar fora da função uma
  variável declarada dentro dela.

C6 - Listas
  Cobrar: acessar o elemento certo a partir de um índice; prever o conteúdo da lista
  depois de push ou splice e o valor de length; combinar laço e condicional para filtrar
  elementos.
  Erros típicos: achar que o primeiro índice é 1; acessar índice igual a length e obter
  undefined; confundir o índice com o valor armazenado; remover itens enquanto percorre a
  lista.

C7 - Git e GitHub
  Cobrar: ordenar os passos para salvar uma alteração no GitHub (add, commit, push);
  explicar para que serve um commit em uma frase; reconhecer o que é um conflito e quando
  ele aparece.
  Erros típicos: achar que salvar o arquivo no editor já versiona a mudança; confundir
  commit (local) com push (envio ao GitHub); supor que Git e GitHub são a mesma coisa;
  achar que clonar e baixar o ZIP são equivalentes.

FORA DE ESCOPO - não cobre nada disso: orientação a objetos, async/await, frameworks,
APIs externas, map/filter/reduce, arrow functions, template literals complexos, objetos
literais complexos, CSS, persistência de dados, back-end, testes automatizados, rebase
interativo, GitHub Actions e estratégias de branching corporativas.

REDAÇÃO E CALIBRAGEM

- Português brasileiro, linguagem direta, sem jargão corporativo. Enunciado de no máximo
  3 linhas.
- Contextos concretos e próximos do público: jogos, música, escola, time, rede social,
  lanchonete.
- Quando o item trouxer código, use JavaScript com no máximo 12 linhas, sem bibliotecas:
  só let/const, if/else, for, while, funções declaradas com function, arrays e
  console.log/alert.
- As alternativas erradas devem sair dos erros típicos listados em cada assunto, nunca ser
  aleatórias: toda alternativa errada precisa ser plausível para quem entendeu em parte.
- Não pergunte nada sobre a plataforma Alura, nomes de instrutores, duração de curso ou
  ordem dos módulos. Avalie raciocínio de programação, não memória do curso.
- Calibragem cognitiva do conjunto: cerca de 6 itens de compreensão, 10 de aplicação e 4
  de análise ou avaliação.
```
