## 2. Texto para colar

```
AVALIAÇÃO PÓS-TRILHA — FRONT-END COM JAVASCRIPT

Contexto: questionário aplicado depois de a trilha ser concluída, em uma ONG que ensina
computação para adolescentes do ensino fundamental II e médio. O estudante já constrói
páginas com HTML e CSS e agora aprendeu a torná-las dinâmicas com JavaScript. Os projetos
fio condutor são aplicações interativas: lista de tarefas, temporizador Pomodoro, mural de
pensamentos com CRUD em API e catálogo de livros com filtros.

ASSUNTOS

C1 - JavaScript na página, seletores e depuração
  Cobrar: dado um elemento no HTML, escrever o seletor que o recupera em JavaScript;
  explicar o que é o DOM e por que o script precisa esperar a página existir; usar o console
  e os breakpoints para descobrir por que um valor chegou errado.
  Erros típicos, para virar alternativa errada: rodar o script antes de a página carregar e
  receber null no seletor; confundir querySelector, que devolve um elemento, com
  querySelectorAll, que devolve uma lista; achar que alterar o DOM muda o arquivo HTML no
  disco; depurar só com console.log, sem olhar a mensagem de erro que o navegador já deu.

C2 - Eventos
  Cobrar: escrever o addEventListener que executa uma função ao clique; distinguir passar a
  função como referência de executá-la na hora do registro; saber por que o envio de um
  formulário precisa de preventDefault.
  Erros típicos: escrever addEventListener('click', minhaFuncao()) e executar a função no
  registro; esquecer preventDefault no submit e ver a página recarregar perdendo os dados;
  registrar o ouvinte em um elemento que ainda não existe na página; registrar o mesmo
  ouvinte várias vezes e a ação acontecer em duplicidade.

C3 - Criar, alterar e remover elementos no DOM
  Cobrar: dado um dado em memória, escrever o código que cria o elemento e o anexa ao
  contêiner certo; trocar a classe de um elemento para mudar o estilo em vez de escrever
  estilo inline; prever o que aparece na tela depois de um trecho que altera textContent e
  atributos.
  Erros típicos: criar o elemento com createElement e esquecer de anexá-lo com append; usar
  innerHTML com conteúdo vindo da pessoa usuária em vez de textContent; alterar style no
  script onde uma classe CSS resolveria; confundir textContent com value em campos de
  formulário.

C4 - Métodos de array
  Cobrar: dado "quero a lista só com os itens disponíveis", escolher filter e não forEach;
  prever o valor devolvido por um reduce que soma um campo da coleção; encadear filter e map
  para transformar e selecionar na mesma passagem.
  Erros típicos: usar forEach esperando que ele devolva um novo array; esquecer o return
  dentro do callback de map ou filter e receber undefined; achar que map filtra elementos
  quando o callback devolve false; usar sort sem função de comparação e ordenar números como
  texto.

C5 - Código assíncrono
  Cobrar: dado um trecho com setTimeout e código depois dele, prever a ordem das saídas;
  reescrever um then/catch como async/await com try/catch; explicar em uma frase por que o
  await precisa estar dentro de uma função async.
  Erros típicos: usar o resultado de uma função assíncrona antes de ela terminar e receber
  uma promise pendente; esquecer o await e tratar a promise como se fosse o valor; achar que
  o setTimeout de 0 ms executa imediatamente, antes do código seguinte; esquecer o
  clearInterval e deixar o temporizador rodando para sempre.

C6 - fetch e CRUD por HTTP
  Cobrar: associar cada operação do CRUD ao método HTTP correspondente; dado um fetch,
  apontar onde a resposta é convertida em objeto JavaScript; reconhecer o significado dos
  status 200, 201, 404 e 500.
  Erros típicos: usar GET para enviar dados que deveriam ir no corpo de um POST; esquecer o
  .json() e tratar a resposta como se já fosse o objeto; confundir PUT, que substitui o
  recurso, com PATCH, que altera parte dele; achar que o fetch devolve os dados direto, sem
  passar pela promise.

C7 - localStorage, datas, expressões regulares e Set
  Cobrar: saber que o localStorage guarda texto e que o objeto precisa ser serializado para
  JSON; dada uma regra de preenchimento, escolher a expressão regular que a valida;
  reconhecer que o Set descarta valores repetidos ao ser construído.
  Erros típicos: gravar um objeto no localStorage sem JSON.stringify e salvar o texto
  [object Object]; ler do localStorage e esquecer o JSON.parse antes de usar como objeto;
  achar que o localStorage é compartilhado entre navegadores ou dispositivos; confundir o
  mês do objeto Date, que começa em zero, com o mês do calendário.

C8 - Módulos, Node e NPM
  Cobrar: escrever o export e o import que compartilham uma função entre dois arquivos;
  distinguir uma dependência de desenvolvimento de uma de produção pelo que ela serve;
  explicar o papel do package.json em um projeto front-end.
  Erros típicos: confundir export default com export nomeado na hora de importar; esquecer o
  type="module" no script e o import não funcionar no navegador; instalar como dependência
  de produção uma ferramenta que só serve para desenvolver; versionar a pasta node_modules
  junto com o projeto.

FORA DE ESCOPO - não cobre nada disso: React, Vue, Angular e qualquer framework de
interface, TypeScript, Web Components, service workers, Web Workers, streams, canvas,
IndexedDB, cookies e sessão no servidor, autenticação e tokens, CORS em detalhe, escrever o
back-end da API, GraphQL, WebSockets, Node.js no servidor, monorepos, Docker e pipelines de
CI/CD. Também não cobre HTML e CSS por si: eles aparecem só como suporte ao JavaScript.

REDAÇÃO E CALIBRAGEM

- Português brasileiro, linguagem direta, sem jargão corporativo. Enunciado de no máximo
  3 linhas.
- Contextos concretos e próximos do público: lista de tarefas, catálogo de jogos,
  temporizador de estudo, playlist, mural de recados, placar de um campeonato.
- Quando o item trouxer código, use JavaScript com no máximo 15 linhas, sem framework e sem
  biblioteca externa — a única exceção é o Axios, nos itens de C6. Nos itens de código,
  descreva em texto o efeito esperado na página; não dependa de o estudante ver a tela.
- Nada de pegadinha de sintaxe fora do que a trilha ensinou. Se o erro a ser detectado for
  de digitação e não de conceito, o item não serve.
- As alternativas erradas devem sair dos erros típicos listados em cada assunto, nunca ser
  aleatórias: toda alternativa errada precisa ser plausível para quem entendeu em parte.
- Não pergunte nada sobre a plataforma Alura, nomes de instrutores, duração de curso ou
  ordem dos módulos. Avalie conhecimento de JavaScript, não memória do curso.
- Calibragem cognitiva do conjunto: cerca de 5 itens de compreensão, 11 de aplicação e 4
  de análise ou avaliação.
```
