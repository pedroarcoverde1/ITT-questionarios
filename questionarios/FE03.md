## 1 · Múltipla escolha · C1 JavaScript na página e seletores · com código

O `app.js` deveria trocar o título da lista de tarefas, mas o console acusa
`Uncaught TypeError: Cannot set properties of null`. Qual é a causa?

```html
<!-- index.html -->
<head>
  <script src="app.js"></script>
</head>
<body>
  <h1 class="titulo">Minhas tarefas</h1>
</body>
```

```js
// app.js
const titulo = document.querySelector('.titulo');
titulo.textContent = 'Tarefas de hoje';
```

- **A)** O script foi carregado no `<head>` e rodou antes de o `<h1>` existir no DOM, então
  `querySelector` devolveu `null`.
- **B)** `querySelector` não aceita seletor de classe; para classes é preciso usar
  `getElementsByClassName`.
- **C)** `textContent` não existe em um `<h1>`; o certo nesse caso é `value`.
- **D)** A alteração não pode ser feita por script: só vale o que estiver salvo no arquivo
  `index.html`.

**Gabarito: A.** Mover o `<script>` para o fim do `<body>`, ou usar `defer`, resolve.
**B** confunde a família de seletores; **C** confunde `textContent` com `value`; **D** é a
ideia de que mexer no DOM mexe no arquivo em disco.

## 2 · Múltipla escolha · C1 JavaScript na página e seletores

O que é o DOM, e o que diferencia `querySelector` de `querySelectorAll`?

- **A)** O DOM é a representação da página em objetos, que o JavaScript pode ler e alterar;
  `querySelector` devolve o **primeiro** elemento que casa com o seletor e
  `querySelectorAll` devolve uma **lista** com todos.
- **B)** O DOM é o arquivo HTML guardado no disco; os dois métodos devolvem listas, e a
  diferença é quantos seletores cada um aceita.
- **C)** O DOM é o CSS aplicado à página; `querySelectorAll` devolve o primeiro elemento, e
  os demais são acessados por índice depois.
- **D)** O DOM é o código JavaScript carregado pelo navegador; os dois métodos são
  equivalentes e a escolha é questão de estilo.

**Gabarito: A.** **B** confunde o DOM com o arquivo; **C** confunde o DOM com o estilo e
inverte os dois métodos; **D** apaga a diferença entre elemento e lista.

## 3 · Múltipla escolha · C2 Eventos · com código

Ao abrir a página do temporizador, a mensagem `contagem iniciada` aparece no console sem
ninguém ter clicado — e clicar no botão não faz mais nada. Por quê?

```js
const botao = document.querySelector('#iniciar');
let segundos = 0;

function iniciarContagem() {
  segundos = 25 * 60;
  console.log('contagem iniciada');
}

botao.addEventListener('click', iniciarContagem());
```

- **A)** Os parênteses em `iniciarContagem()` executaram a função na hora do registro, e o
  que virou ouvinte foi o `undefined` que ela devolveu.
- **B)** Falta `preventDefault()` dentro da função, então o navegador recarrega a página e
  perde o clique.
- **C)** O botão ainda não existia quando o ouvinte foi registrado, então o clique não
  encontra a função.
- **D)** O ouvinte foi registrado duas vezes, por isso a função dispara sozinha uma vez.

**Gabarito: A.** O certo é passar a referência: `addEventListener('click', iniciarContagem)`.
**B** aplica `preventDefault` fora do lugar; **C** descreveria um erro na linha do
`querySelector`; **D** causaria ação em duplicidade depois do clique, não antes.

## 5 · Múltipla escolha · C3 Criar e alterar elementos no DOM · com código

A função roda sem nenhum erro no console, mas nada aparece na lista da página. Qual correção
faz a tarefa aparecer?

```js
const lista = document.querySelector('#lista-tarefas');

function adicionarTarefa(texto) {
  const item = document.createElement('li');
  item.textContent = texto;
  item.classList.add('tarefa');
}

adicionarTarefa('Estudar JavaScript');
```

- **A)** Acrescentar `lista.append(item)` no fim da função: o `<li>` foi criado em memória,
  mas nunca anexado ao DOM.
- **B)** Trocar `textContent` por `innerHTML`, porque `textContent` não escreve dentro do
  `<li>`.
- **C)** Trocar `classList.add('tarefa')` por `item.style.display = 'block'`, porque a classe
  está escondendo o elemento.
- **D)** Declarar `const item` fora da função: variáveis criadas dentro dela são descartadas
  no fim da execução e o `<li>` não chega à página.

**Gabarito: A.** `createElement` cria; só `append` (ou `appendChild`) insere.
**B** confunde o papel de `textContent`; **C** troca classe por estilo inline sem motivo;
**D** confunde escopo da variável com presença no DOM.

## 8 · Múltipla escolha · C4 Métodos de array · com código

O objetivo é obter um array só com os livros disponíveis. O que aparece no console e qual é a
correção?

```js
const livros = [
  { titulo: 'Duna', preco: 60, disponivel: true },
  { titulo: 'Fundação', preco: 45, disponivel: false },
  { titulo: 'Neuromancer', preco: 52, disponivel: true },
];

const resultado = livros.forEach((livro) => livro.disponivel);
console.log(resultado);
```

- **A)** `undefined` — `forEach` percorre mas não devolve nada; o método para selecionar

- **B)** `[true, false, true]` — `forEach` devolve o resultado do callback; para obter os
  objetos bastaria trocar por `map`.
- **C)** Os dois livros disponíveis — o código já faz o que se pretende.
- **D)** Um erro, porque o callback de `forEach` precisa de `return` explícito.

**Gabarito: A.** **B** confunde `forEach` com `map` (e `map` também não filtraria); **C** supõe
que devolver `true` seleciona o item; **D** confunde ausência de retorno com erro.

## 12 · Múltipla escolha · C5 Código assíncrono

Qual reescrita com `async/await` equivale a
`buscar().then((d) => mostrar(d)).catch((e) => avisar(e))` — e por que o `await` precisa estar
dentro de uma função `async`?

- **A)** `async function carregar() { try { const d = await buscar(); mostrar(d); } catch (e) { avisar(e); } }`
  — é o `async` que permite à função pausar no `await` e retomar quando a promise resolver.
- **B)** `function carregar() { const d = await buscar(); mostrar(d); }` — o `await` funciona
  em qualquer função, e o `async` é opcional.
- **C)** `async function carregar() { const d = buscar(); mostrar(d); }` — dentro de uma
  função `async` o `await` é dispensável.
- **D)** `async function carregar() { buscar().then(mostrar); }` — `async` e `then` fazem a
  mesma coisa e podem ser usados juntos assim.

**Gabarito: A.** O `try/catch` ocupa o lugar do `.catch()`.
**B** usa `await` fora de `async`, o que é erro; **C** entrega a promise a `mostrar` em vez do
valor; **D** não trata o erro e não usa `await`.

## 13 · Dissertativa · C5 Código assíncrono

Um colega escreveu, no catálogo de livros:

> `const livros = buscarLivros();` e, na linha seguinte, `console.log(livros.length);`

No console aparece `Promise { <pending> }` e depois um erro. Explique por que isso acontece e
como corrigir.

**O que a resposta precisa conter:**

1. Que `buscarLivros()` é assíncrona e devolve uma **promise**, não os dados: a linha
   seguinte roda antes de a busca terminar (ponto principal).
2. Que `livros` é a promise, e uma promise não tem `length` — daí o erro.
3. A correção: `const livros = await buscarLivros();` dentro de uma função `async` (ou tratar
   o resultado dentro de um `.then()`), de modo que a leitura só aconteça depois de a promise
   resolver.

**Faixas:** os três pontos = integral · pontos 1 e 3, sem explicar o erro do `length` =
parcial · só "faltou await" sem dizer o que é a promise pendente = nulo.

## 14 · Múltipla escolha · C6 fetch e CRUD por HTTP · com código

A função deveria listar os pensamentos do mural, mas o console acusa
`pensamentos.forEach is not a function`. Qual é a correção?

```js
async function carregarPensamentos() {
  const resposta = await fetch('http://localhost:3000/pensamentos');
  const pensamentos = resposta;
  pensamentos.forEach((p) => console.log(p.conteudo));
}
```

- **A)** Converter o corpo da resposta: `const pensamentos = await resposta.json();`.
- **B)** Acrescentar `await` antes do `forEach`, porque a lista ainda é uma promise pendente.
- **C)** Trocar `await fetch(...)` por `fetch(...).then(...)`: `fetch` não funciona com
  `await`.
- **D)** Trocar o método da requisição para `POST`, porque é ela que vai buscar os dados no
  servidor.

**Gabarito: A.** `fetch` devolve um objeto `Response`; os dados saem de `.json()`.
**B** confunde o `Response` com uma promise não resolvida; **C** nega que `fetch` devolva
promise; **D** troca `GET` por `POST`.

## 19 · múltipla escolha · c8 módulos, node e npm

um arquivo tem `export default function criarcard() { ... }` e outro escreve
`import { criarcard } from './card.js';` — e o import falha. por quê, e para que serve o
`package.json`?

- **a)** um `export default` é importado **sem** chaves (`import criarcard from './card.js'`);
  as chaves são para exports nomeados. o `package.json` declara as dependências e os scripts
  do projeto.
- **b)** o import falha porque o caminho precisa ser absoluto; o `package.json` guarda o
  código já compilado do projeto.
- **c)** `export default` só funciona no node, não no navegador; o `package.json` lista os
  arquivos que serão enviados ao navegador.
- **d)** os dois formatos são equivalentes, e o erro vem de faltar `type="module"` no script;
  o `package.json` guarda as versões de navegador suportadas.

**Gabarito: A.** **B** e **C** inventam restrições de caminho e ambiente; **D** cita um erro
real de outro contexto, mas não o que explica a falha com chaves.
