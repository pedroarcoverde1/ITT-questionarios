## 3 · Múltipla escolha · C2 Scripts em C# e ciclo de vida · com código

O console enche de mensagens e a vida do inimigo nunca diminui, por mais dano que ele receba.
Qual é a causa?

```csharp
public class Inimigo : MonoBehaviour
{
    private int vida;

    void Update()
    {
        vida = 100;
        Debug.Log("Vida do inimigo: " + vida);
    }
}
```

- **A)** A inicialização está no lugar errado: `Update()` roda a cada quadro, então a vida
  volta a 100 e a mensagem se repete sem parar. O que acontece uma vez só vai em `Start()`.
- **B)** O problema é `vida` ser `private`: em `Update()` só se pode alterar campos públicos.
- **C)** Falta multiplicar por `Time.deltaTime`, que é o que impede o valor de se repetir.
- **D)** O script não foi anexado a nenhum GameObject, por isso o `Update()` roda sem
  controle.

**Gabarito: A.** **B** inventa uma restrição de visibilidade; **C** usa `Time.deltaTime` fora
do seu propósito, que é escalar movimento pelo tempo; **D** se o script não estivesse
anexado, o `Update()` não rodaria nenhuma vez.

## 4 · Múltipla escolha · C2 Scripts em C# e ciclo de vida · com código

A nave atravessa a tela num piscar de olhos — e, em um computador mais rápido, vai ainda
mais rápido. Qual é a correção?

```csharp
public class Nave : MonoBehaviour
{
    public float velocidade = 5f;

    void Update()
    {
        transform.Translate(Vector3.right * velocidade);
    }
}
```

- **A)** Falta `Time.deltaTime`: como `Update()` roda a cada quadro, o deslocamento precisa
  ser proporcional à duração do quadro — `Vector3.right * velocidade * Time.deltaTime`.
- **B)** O valor de `velocidade` está alto demais: basta reduzi-lo até o movimento ficar bom
  nesse computador.
- **C)** O movimento deveria estar em `Start()`, que roda uma vez e não se repete.
- **D)** O certo é abandonar `Translate` e alterar `transform.position` direto, que é
  independente do quadro.

**Gabarito: A.** Sem `Time.deltaTime`, a velocidade do jogo passa a depender da máquina.
**B** calibra para um computador só e mantém o problema; **C** mataria o movimento; **D** não
resolve nada — a dependência do quadro continua.

## 6 · Múltipla escolha · C3 Entrada da pessoa jogadora · com código

Segurando a barra de espaço, o personagem pula sem parar e sobe indefinidamente. Qual é a
causa e a correção?

```csharp
void Update()
{
    if (Input.GetKey(KeyCode.Space))
    {
        Pular();
    }
}
```

- **A)** `GetKey` é verdadeiro em **todo quadro** em que a tecla está pressionada. Para uma
  ação por toque, o certo é `GetKeyDown`, verdadeiro só no quadro em que a tecla foi
  pressionada.
- **B)** A leitura deveria estar em `Start()`, para registrar a tecla uma única vez.
- **C)** Falta multiplicar o pulo por `Time.deltaTime` dentro do `if`.
- **D)** O erro é usar `KeyCode.Space`: o pulo precisa estar amarrado ao eixo vertical do
  input.

**Gabarito: A.** **B** deixaria o controle sem resposta; **C** suavizaria a força, mas o pulo
continuaria disparando a cada quadro; **D** troca a leitura por outra que também seria
contínua.

## 8 · Múltipla escolha · C4 Física 2D e colisões · com código

A moeda tem sprite e este script; o personagem já tem `Rigidbody2D` e `Collider2D`. Mesmo
assim, ele passa por cima da moeda e nada acontece. O que falta?

```csharp
public class Moeda : MonoBehaviour
{
    void OnTriggerEnter2D(Collider2D outro)
    {
        if (outro.CompareTag("Player"))
        {
            Pontuacao.Somar(10);
            Destroy(gameObject);
        }
    }
}
```

- **A)** Falta um `Collider2D` na moeda, com **Is Trigger** marcado: sem collider não há o
  que detectar o contato, e `OnTriggerEnter2D` nunca é chamado.
- **B)** Falta um `Rigidbody2D` na moeda, para que ela caia e encoste no personagem.
- **C)** O método deveria ser `OnCollisionEnter2D`, porque trigger não detecta o personagem.
- **D)** A ordem está errada: `Destroy(gameObject)` deveria vir antes de somar a pontuação.

**Gabarito: A.** **B** faria a moeda cair, o que não é o problema; **C** passaria a bloquear o
personagem em vez de deixá-lo atravessar; **D** inverteria para a ordem errada — destruir
antes de somar é que perderia a pontuação.

## 13 · Múltipla escolha · C6 Tilemap e sistema de dano · com código

O personagem continua vivo com vida negativa e só morre no dano seguinte. Qual é a causa?

```csharp
public class Vida : MonoBehaviour
{
    public int pontosDeVida = 3;

    public void ReceberDano(int dano)
    {
        if (pontosDeVida <= 0)
        {
            Morrer();
        }
        pontosDeVida -= dano;
    }
}
```

- **A)** A verificação da morte está **antes** da subtração: é preciso subtrair o dano
  primeiro e só então checar se `pontosDeVida <= 0`.
- **B)** O campo deveria ser `private`, e é por isso que a vida não é atualizada.
- **C)** Falta multiplicar o dano por `Time.deltaTime`, para que ele seja aplicado por quadro.
- **D)** `Morrer()` deveria estar em `Update()`, que é onde a condição é avaliada a cada
  quadro.

**Gabarito: A.** No formato atual, a morte é sempre avaliada com a vida do golpe anterior.
**B** não muda ordem nenhuma; **C** transformaria dano por golpe em dano contínuo; **D**
passaria a checar a morte a cada quadro, mas o problema é a ordem dentro do método.

## 20 · Dissertativa · C8 Áudio, vitória, derrota e reinício

Depois de perder, a pessoa reinicia a fase e o jogo começa com a pontuação do jogo anterior
já somada. Explique o que recarregar a cena realmente refaz, por que a pontuação pode
sobreviver a isso, e o que fazer para corrigir.

**O que a resposta precisa conter:**

1. Que recarregar a cena recria os GameObjects e seus componentes, voltando aos valores
   iniciais daquela cena (ponto principal).
2. Que uma variável **estática** (ou um objeto preservado entre cenas) não pertence à cena e
   por isso conserva o valor da partida anterior — daí a pontuação antiga reaparecer.
3. A correção: zerar esse estado explicitamente ao iniciar a partida, em vez de confiar no
   recarregamento da cena.

**Faixas:** os três pontos = integral · pontos 1 e 3, sem explicar por que o valor sobrevive =
parcial · só "é um bug do reinício" = nulo.
