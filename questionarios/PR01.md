## 3 · Múltipla escolha · C2 Variáveis, tipos e entrada/saída · com código

Qual valor aparece no console?

```js
let pontos = 10;
pontos = pontos + 5;
pontos = pontos - 3;

let bonus = "2";
pontos = pontos + bonus;

console.log(pontos);
```

- **A)** `122`, como texto: `bonus` é uma string, então a última linha concatena em vez de
  somar.
- **B)** `14`
- **C)** `12`
- **D)** Um erro, porque não é possível somar um número com um texto.

**Gabarito: A.** 10 + 5 − 3 = 12 e, em seguida, `12 + "2"` vira `"122"`.
**B** soma 12 + 2 como se `bonus` fosse número; **C** ignora a última linha; **D** supõe que
a mistura de tipos interrompe o programa.

## 6 · Múltipla escolha · C3 Condicionais e operadores · com código

O que é escrito no console?

```js
let nota = 7;

if (nota >= 9) {
  console.log("Excelente");
} else if (nota >= 7) {
  console.log("Aprovado");
} else if (nota >= 5) {
  console.log("Recuperação");
} else {
  console.log("Reprovado");
}
```

- **A)** `Aprovado`
- **B)** `Excelente`
- **C)** `Aprovado` e, na linha seguinte, `Recuperação`, porque 7 satisfaz as duas condições.
- **D)** `Recuperação`

**Gabarito: A.** Em um encadeamento `if / else if`, só o primeiro ramo verdadeiro executa.
**C** é a confusão entre `else if` e `if` independentes; **B** e **D** leem a condição errada.

## 7 · Múltipla escolha · C3 Condicionais e operadores · com código

A bilheteria percebeu que ninguém nunca recebe "Ingresso inteira". Qual é a causa e a
correção?

```js
let idade = 20;

if (idade >= 12) {
  console.log("Ingresso meia-entrada");
} else if (idade >= 18) {
  console.log("Ingresso inteira");
} else {
  console.log("Entrada gratuita");
}
```

- **A)** A ordem dos testes deixa o segundo ramo inalcançável: quem tem 18 ou mais já é
  pego pelo primeiro `if`; basta testar `idade >= 18` antes.
- **B)** Os `else if` deveriam ser `if` independentes, para que cada condição seja testada.
- **C)** O erro está em usar `>=`: comparação de idade pede `=`.
- **D)** Faltam `&&` ligando as duas condições em um único `if`.

**Gabarito: A.** Em um encadeamento, os testes mais restritivos vêm primeiro.
**B** faria duas mensagens aparecerem juntas; **C** usaria atribuição onde se compara;
**D** não resolve a ordem.

## 9 · Dissertativa · C3 Condicionais e operadores

Um colega classificou notas com três `if` independentes — `nota >= 9` imprime "Excelente",
`nota >= 7` imprime "Aprovado" e `nota >= 5` imprime "Recuperação" — e percebeu que a nota 9
imprime as três mensagens. Explique por que isso acontece e o que mudar.

**O que a resposta precisa conter:**

1. Que `if` independentes são testados todos, um por um, e a nota 9 torna as três condições
   verdadeiras (ponto principal).
2. Que a correção é encadear com `else if`, para que só o primeiro ramo verdadeiro execute.
3. Reconhecer que a ordem dos testes precisa ir do mais restritivo para o menos restritivo.

**Faixas:** os três pontos = integral · pontos 1 e 2 = parcial · só percebe que "está
errado" sem explicar o teste independente = nulo.

## 14 · Múltipla escolha · C5 Funções com parâmetros e retorno

A função `function dividir(a, b) { return a / b; }` foi chamada como `dividir(2, 10)`

- **A)** A ordem dos argumentos foi trocada: o primeiro valor da chamada vira `a` e o

## 15 · Dissertativa · C5 Funções com parâmetros e retorno

No site de uma lanchonete, o mesmo cálculo de preço com 10% de desconto aparece copiado em
quatro lugares diferentes. Explique por que vale transformá-lo em função e diga o que essa
função precisa receber e o que precisa devolver.

**O que a resposta precisa conter:**

1. Um motivo real de extrair: a regra fica em um só lugar, e mudar o desconto exige uma
   alteração em vez de quatro (ponto principal).
2. Que a função recebe o preço como parâmetro.
3. Que a função **devolve** o preço com desconto com `return`, em vez de apenas mostrá-lo —
   porque quem chamou precisa usar o valor.

**Faixas:** os três pontos = integral · pontos 1 e 2, sem distinguir `return` de exibir =
parcial · só "fica mais organizado", sem dizer o que entra e o que sai = nulo.

## 16 · Múltipla escolha · C6 Listas · com código

Qual valor aparece no console?

```js
let notas = [7, 4, 9, 6, 10];
let aprovadas = [];

for (let i = 0; i < notas.length; i++) {
  if (notas[i] >= 7) {
    aprovadas.push(notas[i]);
  }
}

console.log(aprovadas.length);
```

- **A)** `3`
- **B)** `5`
- **C)** `2`
- **D)** `undefined`, porque o laço chega a um índice que não existe na lista.

**Gabarito: A.** Passam 7, 9 e 10.
**B** supõe que `push` copia tudo, ignorando o `if`; **C** lê `>=` como `>` e descarta o 7;
**D** supõe que a condição `i < notas.length` ultrapassa o fim da lista.

## 17 · Múltipla escolha · C6 Listas

Na lista `let generos = ['rock', 'pop', 'mpb', 'jazz'];`, qual expressão devolve `'mpb'` e

- **D)** `generos['mpb']`, e `length` vale `4`.

## 18 · Múltipla resposta · C6 Listas

Quais afirmações sobre índices e `length` de uma lista estão corretas? (marque todas)

- **A)** O primeiro elemento de uma lista fica no índice `0`.
- **B)** `length` devolve a quantidade de elementos, não o índice do último.
- **C)** Acessar o índice igual a `length` devolve o último elemento da lista.
- **D)** `push` insere no fim da lista e aumenta o `length` em 1.
- **E)** Remover um item enquanto se percorre a lista com `for` não afeta os índices das
  posições seguintes.

**Gabarito: A, B e D.**
**C** devolve `undefined` — o último elemento está em `length - 1`; **E** é falso: remover
desloca todos os itens seguintes e o laço pula elementos.

## 20 · Múltipla resposta · C7 Git e GitHub

Quais afirmações estão corretas? (marque todas)

- **A)** Salvar o arquivo no editor já registra a alteração no histórico do Git.
- **B)** `git add` seleciona quais alterações entram no próximo commit.
- **C)** `git commit` grava a alteração no histórico, que fica no seu computador.
- **D)** `git push` envia os commits locais para o repositório no GitHub.
- **E)** Git e GitHub são a mesma ferramenta, então o commit já aparece no site.

**Gabarito: B, C e D.**
**A** confunde salvar com versionar; **E** confunde o Git (programa de versionamento, local)
com o GitHub (serviço que hospeda os repositórios).
